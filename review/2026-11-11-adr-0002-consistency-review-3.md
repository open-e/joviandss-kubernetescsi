## Verdict

Today's changes are consistent with each other and with the rest of the record, with one exception that I introduced this afternoon: Table 2 now says snapshot `name` is required in list entries only, and the NFS driver reads it from the reply by name as well. The other inconsistency is structural and known: the README now says a record does not list unit tests, and the record lists them in five items, in Testing and in two risk guards; that waits on the user's answer to the testing review's first question. The rest is four small wording points. The numbering, the anchors, the names, the references and the counts all hold.

## Medium

1. **Table 2 is now too narrow about snapshot `name`** (the row "a required read field absent from a reply"). This afternoon's fix made it "snapshot `name` in list entries only: the zvol snapshot reply by name carries no `name` … and nothing reads it there". The NAS snapshot reply by name does carry `name`, as the catalogue entry says ("NAS snapshot GETs do"), and the NFS driver reads it: `nfs_driver.go:566` and `:589` set `Name: nv.Name` from `GetNASVolumeSnapshot`. So `name` is a read field in three places, the all-snapshots list, the NAS snapshot by name, and not the zvol snapshot by name. The row should say "snapshot `name` in list entries and in the NAS snapshot reply by name; the zvol snapshot reply by name carries no `name` ([bug_plugin_rest_zvol_snapshot_name_missing]) and nothing reads it there". No decision needed; the generator's mapping is per endpoint anyway.
2. **The record lists unit tests; the README now says it does not.** Since this afternoon the README's What changes row says an item states "what must hold once it is done" and that "the unit tests that show an item works are the implementing agent's, not the record's", and the Testing row says "no unit tests". The record still prescribes them: `impl_plugin_rest_error_catalogue` ("A unit test … would run every recorded error body"), `impl_plugin_rest_crash_fixes` ("Each gets a unit test: a fake server that …"), `impl_plugin_rest_no_request_logging`, `impl_plugin_rest_escape_path_segments`, and `impl_plugin_rest_fixtures_and_unit_tests` as a whole; Testing step 1's inventory, step 3 and step 9; the guards of risks 4 and 18; the "Unit tests and audit" row of Affected systems and the `pkg/rest/*_test.go` row of Table 3; the Terms row "fixture". The testing review of this afternoon asks the user whether each item keeps one line of what must hold or loses its test sentences; until that is answered the README and the record disagree, and the fix is the same whichever way it goes: the fixtures (recorded replies, trimmed, secrets removed, questions 4 and 19) stay a deliverable with rules, the test inventories go, each item keeps its condition.

## Low

3. **Metadata's `Date:` lists two decisions; the README says each.** The README's Metadata row reads "`Date:` when each decision was taken"; the record's Date names 2026-11-05 and 2026-11-10 and not today's decision of question 29, which Advice dates. Practice since the merge is that the headline decisions go in Date and the question decisions in Advice. Say so in the README row ("the decisions of the Options section; the question decisions are dated in Advice"), rather than growing Date with every question.
4. **Context states the older-release decision as a fact.** "What we do not know" now says "they do not serve the same v4 and are not supported ([question 29], [risk 2])" in the voice of the recordings, while risk 2 attributes the same sentence to the user ("user decision"). Context carries facts and the evidence; the sentence should say whose statement it is: "no such appliance was available; the user states that they do not serve the same v4, so none is supported".
5. **"Backward compatibility, not preserved"** names "appliances on a JovianDSS 1 release without v4"; risk 2 and Option A say "without v4, or with a different v4". One phrase for symmetry.
6. **The README's "Checks before a review"** does not know the two forms added today: a list with gaps is written as bullets with the number in bold, and every Testing step names where it runs and who runs it. Two clauses.
